# Ключ подписи

`debug.keystore` — постоянный ключ, которым подписываются **все** сборки APK
из этого репозитория. Сгенерирован один раз 2026-11-16 workflow
`.github/workflows/signing-key.yml` (JDK 17, `keytool`).

## Параметры

| | |
|---|---|
| файл | `signing/debug.keystore` |
| формат | JKS |
| alias | `androiddebugkey` |
| storepass / keypass | `android` |
| алгоритм | RSA 2048 |
| срок | 10950 дней (30 лет) |
| sha256 файла | `e11e86206ee5e6139e09b5f4f12c9805f9f4cd5d792dabb6d32432769d6ad650` |

Пароли стандартные для debug-сборки AGP — поэтому `app/build.gradle.kts` и
команда сборки не меняются: workflow просто кладёт файл в
`$HOME/.android/debug.keystore`, откуда его берёт стандартная debug-подпись.

## Зачем он в репозитории

Ключ, которым был подписан первый APK, генерировался на PC в
`~/.android/debug.keystore` и был потерян. Android не даёт обновить приложение
другим ключом (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), а удаление приложения
стирает его данные. Чтобы это не повторилось, ключ лежит здесь: он не теряется
вместе с машиной, и CI берёт его сам, без секретов.

Побочный эффект: репозиторий публичный, значит ключ публичен. Теоретически
кто-то может собрать APK с той же подписью — но установить его можно только
вручную, автоподмены не будет. Если это станет неприятным, ключ переезжает в
секрет `ANDROID_DEBUG_KEYSTORE_BASE64` (base64 файла): workflow сначала
смотрит секрет и только потом сюда.

## Проверки в сборке

1. `keytool -list` печатает отпечаток ключа в лог.
2. После сборки `keytool -printcert -jarfile` сверяет отпечаток **APK** с
   отпечатком этого ключа; расхождение — падение сборки, а не «наверное, сойдётся».

## Если ключ всё же понадобится пересоздать

Тогда все установленные копии придётся один раз удалить (данные — сохранить
заранее), потому что подпись поменяется. Порядок: бэкап данных приложения на
`/sdcard` → удаление → установка нового APK → восстановление данных.
