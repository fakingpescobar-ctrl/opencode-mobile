# Волна 1: временны́е факты, слоты и связи

Дата: 20.11.2026. Отчёт лежит в `архивы/`, чтобы не попасть в поисковый индекс
и не сбить жёсткий gold.

## Что изменилось в ядре

- `CORE_SCHEMA` дополнен таблицами `memory_fact` и `memory_fact_link`.
- `ensureCoreSchema(DB)` точечно добавляет недостающие колонки в старые базы:
  `memory_staged` получает `kind`, `topic_key`, `valid_from`, `confidence`,
  `reason`, `links`; `graph` получает `evidence`.
- `ingest` принимает `kind:"fact"`, `topic_key`, `valid_from`, `confidence`,
  `reason`, `links`. Для факта без `topic_key` — явная ошибка.
- `approve` для факта закрывает прежние активные записи в том же слоте через
  `invalid_at`, пишет типизированные связи, аудит и снапшот. Старый текст
  не удаляется.
- `rollback` возвращает прежний факт в активное состояние и убирает аудит
  откатанной записи. Тихого удаления нет.
- `recallFacts` честно уважает `as_of`; `factStats` даёт счётчики.
- `memoryPack` подмешивает факты только при совпадении с запросом. Веса `W`
  гибридной формулы не менялись.
- `runTemporalBench` считает recall по `pack.sources` с учётом `as_of`.
- `MemoryMcp.toolCounts()` не тронут. Новых MCP-инструментов нет: режим фактов
  включается параметром `facts` в `memory_pack`, временной бенч — параметром
  `suite:"temporal"` в `memory_bench`, счётчики видны в `memory_index_stats`.

## Новый gold

`MOBILE_AGENT/memory/gold-temporal.jsonl` — 16 детерминированных кейсов
с явными идентификаторами фактов. Покрывает текущее и прошлое состояние
слотов, откат, типизированные связи и чужой слот.
