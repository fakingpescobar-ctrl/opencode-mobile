# Qwen3-TTS: research-гейт ARM ISA `dotprod`/`i8mm` (CPH2747, 28.11.2026)

**Состояние на момент записи: гейт зафиксирован до правки. Результат ещё не измерен.**

По явному решению Макса открыт новый гейт под конкретный рычаг после DROP резидентного замера G1c. Режим: **research/bench only**. APK wiring, CI-release и установка APK не открываются; Supertonic остаётся default.

## 1. Почему именно этот рычаг

В `MOBILE_AGENT/tmp/qwentts/build-qwentts-musl.yml:59` research-сборка идёт с `-DGGML_NATIVE=OFF`, а `GGML_CPU_ARM_ARCH` не задан. В pinned ggml `ServeurpersoCom/ggml @ ef4555b`:

- `src/ggml-cpu/CMakeLists.txt:209-211`: при `GGML_NATIVE=OFF` флаг `-march=` добавляется **только** из `GGML_CPU_ARM_ARCH`;
- `src/ggml-cpu/arch/arm/quants.c` и `repack.cpp` содержат быстрые ветки под `__ARM_FEATURE_DOTPROD` и `__ARM_FEATURE_MATMUL_INT8`;
- `src/CMakeLists.txt:526-533` перечисляет готовые варианты `armv8.2_1 DOTPROD`, `armv8.6_1 … MATMUL_INT8`, `armv8.6_2 … SVE2`.

То есть эталон собран под базовый ARMv8-A и эти ветки в него **не попали**. На CPH2747 (Oryon, ARMv9) `dotprod`/`i8mm` аппаратно есть; в G1 уже использовался бэкенд `armv8.6_1`, то есть совместимость на устройстве подтверждена, но выигрыш для qwentts.cpp не измерялся.

Это **не** правка весов и не правка графа: меняется только сборочный флаг, код qwentts.cpp/ggml и модели остаются байт-в-байт теми же.

## 3. Граница правки

Разрешено: новый research-workflow `.github/workflows/build-qwentts-isa.yml` (копия базового + одна строка `-DGGML_CPU_ARM_ARCH=armv8.6-a+dotprod+i8mm`), этот документ, scratch-раннер, `$BASE/bin-isa/`, `$BASE/out-isa/`, записи в журнал/состояние/ядро памяти.

Не трогаются: `$BASE/bin/`, модели, исходники, измерители `bench-resident.mjs` / `run-bun.sh` / `summary-resident.mjs`, `app/`, `release-apk.yml`, `ci.yml`, APK. Supertonic остаётся default.

`bin/` и `out-resident/` эталона могут временно подменяться раннером с обязательным восстановлением; после прогона sha эталона сверяется повторно.

## 4. Гейт (неизменный, применяется один раз)

| Метрика | ACCEPT (только diagnostics-кандидат) | DROP / откат |
|---|---|---|
| RTF med short / medium / long | ≥10% улучшения в каждой категории относительно G1c | <10% или хуже хотя бы в одной |
| Первый PCM med | ≤796.4 мс | >796.4 мс |
| Стабильность | 28/28 HTTP 200, 0 crash/hang, s16le 24 kHz mono | любой 4xx/5xx, обрыв, crash/hang |
| RU/WAV sanity | PCM ненулевой, peak >0.01 | тишина/мусор/иной формат |

Product-гейт RTF ≤1.0 **не пересматривается**: даже ACCEPT не открывает APK wiring и требует отдельного решения Макса. Пороги, число прогонов и протокол после старта не меняются; равный или худший результат — `выбросить` и откат, «почти получилось» не оставляется (правила 58/59/61).

## 5. Что считается доказательством

- CI run зелёный, в логе виден `-march=armv8.6-a+dotprod+i8mm`, артефакт скачан с sha.
- SHA новых бинарей отличаются от эталона (иначе флаг не применился — это провал инфраструктуры, а не «равный результат»).
- Неизменный измеритель дал 28/28, медианы и первый PCM посчитаны тем же `verdict`-подходом с константами из раздела 2.
- После прогона sha эталонных бинарей совпадает с точкой отсчёта, research-workflow удалён с `main`.
