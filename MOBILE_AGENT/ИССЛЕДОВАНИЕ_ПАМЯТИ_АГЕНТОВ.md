Дата: 2026-11-21. Запрос Макса: посмотреть Reddit, GitHub и другие площадки,
найти интересные реализации, инновационные технологии и решения, провести

## Метод и оговорки

Работали четыре сабагента параллельно:

1. `general` — GitHub-экосистема (звёзды, архитектуры, лицензии, бенчмарки);
2. `general` — Reddit / Hacker News / инженерные блоги, живой опыт практиков;
3. `general` — научные работы и новые механизмы 2023–2026 (arXiv, код);
4. `explore` — аудит собственного ядра `MOBILE_AGENT/opencode/memory-core/`.

Оговорки, без которых выводы нельзя использовать:

- звёзды GitHub — снимок **21.11.2026** через REST API, это не «пик»;
- `websearch` в сессиях сабагентов падал, источники — GitHub API, raw README,
  arXiv, Arctic Shift (архив Reddit), HN Algolia API и прямой fetch блогов;
- Reddit напрямую недоступен (403/429), Lobsters — за анти-бот проверкой,
  репрезентативный срез Lobsters **не собран**;
- почти все «+N%» в чужих таблицах — self-reported самими вендорами. Дополнительно:
  смена judge и answer prompt в LoCoMo двигает счёт до **7.2** и **9.3** пункта
  ([2611.19199](https://arxiv.org/abs/2611.19199)) — любые лидерборды нужно
  читать только внутри одного протокола, даты и модели-ответчика.

## 2. Что реально нового в 2025–2026

### 2.1. Базовые работы

- **MemGPT** ([2310.08560](https://arxiv.org/abs/2310.08560), 2023) — OS-метафора:
  быстрый контекст + медленные внешние хранилища, модель сама paging-ит через
  function calls. Прямая модель «ядро + диспетчер上下文».
- **Generative Agents** ([2304.03442](https://arxiv.org/abs/2304.03442), 2023) —
  retrieval = recency (exp 0.995) + importance (LLM при создании) + relevance
  (cosine); reflection при сумме importance > 150: 100 последних → 3 вопроса →
  инсайты со ссылками на цитаты. Абляция: 29.89 → 26.88 без reflection.
- **LoCoMo** ([2402.17753](https://arxiv.org/abs/2402.17753), 2024) и
  **LongMemEval** ([2410.10813](https://arxiv.org/abs/2410.10813), ICLR 2025) —
  основные бенчмарки; LongMemEval сообщает ~30% падения у коммерческих ассистентов.
- **A-MEM** ([2502.12110](https://arxiv.org/abs/2502.12110), NeurIPS 2025) —
  Zettelkasten: структурированные note + динамические связи + memory evolution.
- **Mem0** ([2504.19413](https://arxiv.org/abs/2504.19413), 2025) — tool-call
  `ADD/UPDATE/DELETE/NOOP`; графовый вариант инвалидирует устаревшие связи.
- **Zep / Graphiti** ([2501.13956](https://arxiv.org/abs/2501.13956), 2025) —
  битемпоральность `T/T′`, четыре timestamp; при противоречии старому ребру
  ставится `tinvalid = tvalid` нового. Поиск cosine + BM25 + BFS + RRF/MMR.
- **Hindsight** ([2512.12818](https://arxiv.org/abs/2512.12818), 2025) —
  четыре сети `W/B/O/S`, операции `Retain/Recall/Reflect`, RRF + cross-encoder.

### 2.2. Новизна именно 2026 года

| Направление | Работы | Суть |
|---|---|---|
| **Read-time вместо write-time сжатия** | Chain on Demand [2611.02480], Mem++ [2610.02002], MAPE [2611.17068] | Держать сырые turns, строить evidence chain только под запрос; все версии с датой и автором, читать «на момент вопроса» |
| **Evaluate-in-the-loop** | ARISE [2611.23588], EGE [2611.16378], ENGRAM [2611.09472], MEMOIR [2611.07631] | Кандидат коммитится только если выросла **held-out** accuracy; paired audits, non-inferiority, canary; judge-gated merge до сжатия |
| **Обучение на ошибках** | AdMem [2611.20605], How Much Should an Agent Remember? [2611.26361] | Наивная аккумуляция опыта проигрывает memoryless ReAct в 7/8 доменов; «правильное количество памяти — свойство модели» |
| **Забывание и сохранение деталей** | Compaction/decay [2611.09807], MemFolder [2611.26427], DREAM [2610.13267] | Compaction выигрывает 71.4% vs 64.6% на 4 категориях, но на всех 5 отрыв 2.0 п.п. — теряется «как сказано»; выборочное забывание снимает >95% ASQ backdoor |
| **Битемпоральность и read boundaries** | DISCERN [2611.15729], Read Boundaries [2611.19264], TrackMem [2611.02001] | 199 конфликтующих ответов из 12 010 recalls при spaced writes; read/write lock или epoch validation → 0 конфликтов на 24 020 |
| **Надёжность и invertible forgetting** | LinEra [2611.18133], PerMIT [2610.28987], Securing & Auditing [2611.23346], Accept Changes Reject Attacks [2610.41056] | Без LinEra атакующий восстановил 70/71 «забытый» секрет, с LinEra — 0; audit **state transfers**, hash-chained журнал; формальная устойчивость к outdated + poisoned одновременно |
| **Маленькие open-weight модели** | Hindsight: `hs-decide-1-flash` 0.8B, `hs-rerank-1` 114M, `hs-embed-1` 112M | Единственное подтверждённое «budget-friendly» локальное решение из всего списка |

**MCP как де-факто фронтенд памяти:** reference-серверы у Graphiti, Cognee,
Hindsight, EverOS, OpenViking, Supermemory и codebase-memory-mcp (последний уже
ставит хуки/навыки для **OpenCode**). Но Graphiti прямо предупреждает: reference
MCP/REST **без аутентификации и защиты от prompt injection**. MCPHallu
([2611.07689](https://arxiv.org/abs/2611.07689)) на 36 production MCP-серверах
выделил subtype **Context Forgetting**; [2610.28810](https://arxiv.org/abs/2610.28810)
называет MCP-connected ресурсы одним из векторов持久ной инъекции.

### 2.3. Что говорят практики (Reddit / HN)

Опорные треды:

  сильных моделей; общая таблица условий дала 41/57 фактов, отдельные страницы
  с дословными цитатами — 57/57; Claude Code грузит только первые **200 строк /
  25 КБ** `MEMORY.md` как индекс.
- [Synix, source-level analysis](https://synix.dev/articles/agent-memory-systems/)
  (16.02.2026): у Mem0 `add()` = 2 LLM-вызова, changelog не участвует в retrieval;
  у Graphiti 3+N вызовов на эпизод; у Cognee нет temporal-модели; общий вывод —
  «every one of these systems defines memory as variation of fact extraction,
  storage and retrieval», разрыв с реальными потребностями больше, чем в доках.
- Повторяющиеся боли: 95% автозаметок удаляются вручную; vector db как
  «музей устаревших фактов»;obody не handles `superseded_by` из коробки;
  модели лениво дёргают memory-tools; графы плохо диагностируются и отравляются;
  «simply improving retrieval doesn't necessarily improve final task outcome».

**Сходимость у практиков:** канонический source of truth — append-only
транскрипт + reviewable Markdown, а извлечённые факты — производная
материализация. «The repo would be the canonical source, and FTS5 would be one
specific materialization» ([HN 49290256](https://news.ycombinator.com/item?id=49290256)).
Наш proposal/rollback ложится сюда идеально.

## 3. Наше ядро в этом контексте

Проверено по коду (`memory-core.js`, `memory-index.mjs`, `memory-adaptive.js`,
`memory-llm.js`, `tmp/apk-integrate/mcp/memory.js`).

### 3.1. Что есть

- **22 memory-тула**: 9 старых `local_memory_*` и 13 ядра. `memory_pack` с `why`
  на каждом куске, `memory_recall_doc`, `memory_adaptive`, `memory_feedback`,
  `memory_thread`, `memory_graph`, `memory_bench`, `memory_index_stats`,
  `memory_ingest`/`approve`/`rollback`, `memory_llm_status`/`search`.
- **Детерминированный поиск**: два FTS5 (`trigram` для текста, `unicode61` для
  якорей), Snowball-леммы, 14 групп латинских синонимов, fuzzy-подпоследовательность,
  фиксированные пулы (15/18), дедуп с заменой на канонический источник,
  top-N монотонен по `limit`.
- **Фактические веса** (`memory-core.js:105`):
  `0.45·BM25(doc) + 0.33·BM25(anchor) + 0.10·graph + 0.05·authority + 0.07·recency`,
  умножить на `trust` и `(1 + 0.06·feedback)`.
  ⚠️ В `АРХИТЕКТУРА_ПАМЯТИ.md:110` указаны **устаревшие** 0.40/0.30/0.12/0.10/0.08 —
  исправить.
- **Битемпоральные факты** `valid_from/invalid_at`,的健康 `as_of`, proposal-проход
  (`duplicate`/`merge`/`contradiction`), аудит + snapshot + rollback, provenance
  с авто-применением только своих/operator.
- **Адаптив**: `peak = top1 − median`, пороги 0.62/0.38/0.20, бюджеты 8/12/12/12
  чанков; LLM вызывается только при низком confidence, всегда несёт
  детерминированный pack, при сбое `fallback=true`.
- **Метрики**: ядро **198/0**, интеграция **100/0**, GGUF **109/0**, BAD=0;
  gold и hard **1.000**, временной gold 16/16; 4–11 мс/запрос.

### 3.2. Чего нет (проверено, не предположение)

| Практика | Статус |
|---|---|
| Autosummary / консолидация | **Нет** — ни одной функции summary/consolidate |
| Автоматическое забывание | **Нет** — только recency-ранг и `invalid_at`; TTL/prune/eviction нет |
| Embeddings | **Нет** — проверено и отклонено: семантических провалов на 40 gold не найдено |
| Learned reranker | **Нет** — LLM-селектор дал 0.25 против 1.000 ядра (~7.4 с против 11 мс) |
| Multi-agent namespaces / ACL | **Нет** — нет `agent_id/session/tenant`; разделение только по provenance |
| Замкнутый eval-цикл | **Частично** — ручные bench и gate, нет автопрогона после мутации и автонастройки весов |
| Time-travel | **Частично** — `as_of` + откат staged-записей; но rollback **удаляет** audit и snapshot, индексация Markdown вне аудита, нет привязки чанка к commit/APK |
| Proposal-инструменты в MCP | **Дыра** — `acceptProposal`/`rejectProposal`/`rollbackProposal` экспортируются, но **не зарегистрированы как тулы**; решать можно только кодом внутри процесса |
| Настоящий графовый обход в скоринге | `graphProximity` — дешёвый proxy; реальный обход только в `followThread`/`conceptThread` |
| Near-duplicate | Только точный sha текста |
| Negativity gate | Веса hand-tuned под 20 gold; gate вручную перебазировался (0.90 → 0.85 в истории) |

**Вердикт:** очень прочный детерминированный offline-движок с честной
аудируемостью и малой латентностью, но не система структурированного
долгосрочного обучения. Главная наша дифференциация — **доверие и откат**:
ни один из топ-10 не
реализует `authority/recency/trust/feedback` как взвешенные сигналы +
fact-level approve/rollback с human-in-the-loop. Ближайшие аналоги — proof count
у Hindsight, инвалидация у Graphiti, editable memory у Letta/EverOS — только
кирпичики.

## 4. Бенчмарки: кто «лидирует»

Единого лидера нет. Есть лидеры конкретных протоколов:

| Источник | Протокол | Числа | Оговорка |
|---|---|---|---|
| EverMemOS paper, jan 2026 | LoCoMo 1540 вопр. | EverMemOS 93.05, Zep 85.22, Mem0 64.20 | Вендор, baseline не перезапускались |
| EverOS repo, nov 2026 | LoCoMo / LongMemEval | 94.61 / 94.00 | Одиночный прогон, ре-judged 99 спорных |
| Hindsight, dec 2025 | LongMemEval / LoCoMo | 91.4 / 89.61 | Self-reported, часть «независимо воспроизведено» не проверено |
| Mem0 README, apr 2026 | LoCoMo / LongMemEval | 92.5 / 94.4 | **Managed platform**, проприетарные оптимизации |
| Supermemory | LongMemEval / LoCoMo | 95% Recall@15 | Другая метрика, несравнимо |
| OMEGA / Mastra (memnode, май 2026) | LongMemEval | 95.4 / 94.87 | Вендор с конфликтом интересов |

Критика LoCoMo с двух сторон: Zep исправил собственный результат с +24% до +10%,
простой full-context baseline (~73%) побил лучшую конфигурацию Mem0 (~68%);
в датасете category 5 без ground truth, ошибки BLIP-описаний и атрибуций.

**Нашу 1.000 нужно формулировать честно:** это `recall@5` на **наших 20 gold
вопросах по нашим же документам** — отличный регресс-контроль, но не сравнение
с Hindsight 94.6 на LoCoMo. Разные протоколы.

## 5. Рекомендации по внедрению (ранжировано)

### Tier 1 — дёшево, высокая отдача, можно делать сразу

1. **Зарегистрировать proposal-тулы в MCP** — `acceptProposal`, `rejectProposal`,
   `rollbackProposal`. Сейчас human-in-the-loop контур физически оборван снаружи.
2. **Исправить веса в `АРХИТЕКТУРА_ПАМЯТИ.md:110`** — 0.45/0.33/0.10/0.05/0.07
   вместо устаревших 0.40/0.30/0.12/0.10/0.08.
3. **Held-out gate после каждого approve** — по образцу ARISE/EGE: после коммита
   кандидата автоматически `memory_bench`, при регрессе >2 п.п. — авто-rollback.
   У нас уже есть и bench, и gate, и rollback — осталось замкнуть.
4. **Логировать credit/blame** — `memory_feedback` сейчас бьётся по точному sha
   запроса. Добавить «какие chunk_id реально попали в контекст и помогли/повредили
   исходу», как советуют в r/LangChain `1w2h9fr`.
5. **Read-time evidence chain** — Chain on Demand / Mem++: не переписывать память
   на записи, а под запрос детерминированно подтягивать соседей из того же
   источника/сессии по якорю. У нас уже есть `as_of` и чанки — дешёвое расширение.
6. **`unicode61 tokenchars = -_.`** для `anchor_fts` — технические идентификаторы,
   UUID, тикеры не будут ломаться. Один параметр.

### Tier 2 — средняя стоимость

7. **Приоритет / utility / UCB вместо чистого similarity** — `(1−λ)·sim + λ·Q`,
   пересчёт важности после использования, exploration-бонус для редко берёмых
   записей. Аналог MEMOIR + MemRL без обучения модели.
8. **Гибрид RRF вместо линейной суммы** — для `doc_fts`/`anchor_fts`/графа/recency.
   RRF устойчивее к разным шкалам; практики прямо рекомендуют его вместо сложения
   сырых BM25 и cosine.
9. **Офлайн «dreaming» как сверка, а не фантазия** — Anthropic: проверка заметок
   против транскриптов, исправление, повышение/понижение в иерархии. Но HN `andai`
   считает выигрыш маргинальным относительно wiki + search — делать только как
   проверку, не как генератор правил.
10. **Epoch validation при чтении** — защита от «read boundaries» (199 конфликтов
    из 12 010 recalls). У нас один процесс, но фоновая индексация и параллельные
    сабагенты могут проявить то же самое.
11. **Испробовать `hs-rerank-1` (114M) вместо GBNF-самплера** — GBNF через FFI у нас
    уже давал segfault (долг). Open-weight модель Hindsight — единственный
    бюджетный кандидат. Сначала на нашем 30-вопросном eval, не сразу в прод.

### Tier 3 — пока не брать

- **Embeddings / cross-encoder** — мы уже проверяли и отклоняли; возвращаться только
  если появится значимый провал на нашем же gold.
- **Forgetting / eviction** — в литературе найден `degenerate forgetting`;
  безопаснее оставить recency в ранге и TTL только для эфемерных записей.
- **Multi-agent namespaces** — пока один агент в одном процессе. Понадобится,
  если сабагенты начнут параллельно писать в память.
- **Weight-space consolidation (CLAM, Axis-LoRA)** — слишком тяжело для телефона.

### Безопасность (важно для нашего MCP)

- Reference MCP у Graphiti без auth и защиты от prompt injection — наш сервер
  локальный, но память может травиться внешними источниками (moltbook/web).
  trusted/provenance у нас есть, но добавить hash-chained журнал state transfers
  и явный gate на внешние записи — стоит.
- LinEra: обычное удаление не защищает — 70/71 секрета восстанавливались.
  У нас есть `secret:0`, но при реальной необходимости «forget» нужен lineage-key.
- MCPHallu Context Forgetting — проверять, что отвечающая модель действительно
  видела цитируемую запись, а не достроила её.

## 6. Главные выводы

1. Рынок ушёл от векторной памяти к жизненному циклу; наш proposal/rollback +
   битемпоральность — мейнстрим, а не отсталость.
2. Лидеров бенчмарков нет, есть протоколы. Все «+10%» читать с оговоркой judge
   и prompt (до 9.3 пункта).
3. MCP стал стандартным фронтендом памяти, но reference-серверы уязвимы —
   наша локальная модель здесь выгоднее, если добавить аудит state transfers.
4. Для телефона берём не код целиком, а паттерны: инвалидация (Graphiti),
   proof count (Hindsight), L0/L1/L2 (OpenViking/TencentDB), Markdown как
   source of truth (EverOS), маленькие open-weight модели (Hindsight).
5. Наша недоиспользованная ниша — **доверие и откат**. Ближайшие готовые
   решения не подтверждены; именно здесь стоит строить дифференциацию.
6. Практики всё чаще просто отключают автоматическую память. Значит главный
   критерий — не «нашли ли нужное», а «стало ли действие лучше», и наш
   human-in-the-loop контур надо замкнуть до конца (Tier 1, п. 1 и 3).
