# Закрытие открытых долгов (20.11)

Были записаны три пункта в `СОСТОЯНИЕ.md`. Разобраны все.

## 1. `moltbook-status.test.mjs` — одно падение

Падал только один тест: `status on a directory without a ledger says so instead
of guessing` с сообщением `dir not picked up: ` (пустое значение).

**Диагностика.** Тест сначала импортирует плагин один раз наверху, затем в этом
тесте выставляет `process.env.MCP_MOLTBOOK_DIR` и пытается переимпортировать
модуль с параметром обхода кэша `?dir=<временный каталог>`. В Node это создаёт
новый экземпляр модуля, но Bun кэширует модуль по разрешённому пути и игнорирует
параметр запроса: повторный `import()` возвращает тот же объект (`a === fresh`),
поэтому `MOLTBOOK_DIR` остаётся пустым. Продукт тут ни при чём — это
несовместимость тестовой техники с Bun, под которым мы гоним тесты на телефоне.

Отдельно выяснилось: локальный файл плагина
`MOBILE_AGENT/opencode/moltbook.deploy.js.patched-20261115` не имеет суффикса
`.js`, поэтому Bun не распознаёт в нём именованные экспорты. Это только локальная
ловушка запуска: в репозитории эталон лежит по пути
`app/src/main/assets/mcp/moltbook.js` с нормальным расширением.

**Исправление.** В тесте вместо обхода кэша через параметр запроса теперь
делается копия плагина во временном каталоге, и импорт идёт с нового пути:

```js
const copy = join(dir, "moltbook-copy.mjs");
copyFileSync(MOLTBOOK_JS, copy);
const fresh = await import(pathToFileURL(copy).href);
```

Новый путь гарантирует свежий экземпляр модуля и в Node, и в Bun. Побочно это
снимает и проблему расширения: копия всегда получает `.mjs`. Плагин сам
самодостаточен, относительных импортов внутри нет — проверено.

**Проверка:** `32 ok, 0 broken` на Bun с плагином из репозитория. Код плагина
не менялся, APK не трогался.

## 2. `fetch-natives.sh` — требует `bash`

Скрипт использует `set -euo pipefail`, `local`, `mapfile`, подстановки здесь
и срезы `${var:0:12}`. На телефоне нет ни `bash`, ни `jq`; скрипт в принципе не
предназначен для запуска там — он готовит `jniLibs` для сборки в GitHub Actions,
где bash и jq есть. Переносить его на POSIX sh означало бы переписывать
критичный для CI путь и проверять его только синтаксисом: полного окружения для
прогона здесь нет. Риск больше пользы, поэтому пункт переклассифицирован: это
ограничение среды, а не долг.

## 3. `signing/`, `appdata-backup/`, `.git/`

Лежат снаружи `MOBILE_AGENT/` намеренно: ключ подписи `repo`, резервные копии
данных и служебные каталоги не должны попадать в индекс памяти и в репозиторий.
Удалять или переносить нельзя без явного разрешения Макса. Это решение, а не
долг.
