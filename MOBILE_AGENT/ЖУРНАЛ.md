## 21.11 — Quality-gate: LLM не выбирает чанки (ЗАВЕРШЕНО)

**Что сделано:** после фиксации модели по latency поставил quality-gate на 20
gold-вопросах. Ядро отдаёт 6 кандидатов, модель выбирает до 3. Обёртка v5
получила `lb_gen` (генерация текста) и `lb_gen_g` (GBNF); CI run
`44635871475`, коммит `59bf6c221ef9…`, `.so` sha `de220aed7626…`.

**Ход отладки (важно):** с примером в системном промпте модели дословно
копировали `"why":"кратко почему"` — цифры были фиктивными. Без примера Qwen
выдал голый массив, gemma — `id` вместо `ids`, SmolLM2 повторил промпт.
Попытка GBNF-ограничить формат уронила Bun segfault внутри FFI-моста —
отдельный долг, не вина моделей. Итоговый gate разбирает ответы гибко.

**Результат:** `КАЧЕСТВО_ЛЛМ.md`, `quality-gate.json`. Разбираемый ответ
60/10/25%, recall 24/0/6% у Qwen3-0.6B / gemma-3-270m / SmolLM2 против **65%**
у простого детерминированного топа ядра. Все модели проиграли ядру.

**Вывод:** архитектура усилена — «код не только решает, но и выбирает». LLM
остаётся опциональным сопроцессором для объяснений/переформулировки, выбор
чанков и поле `why` остаются детерминированными. gemma быстрым режимом не
фиксируется. Запись в `ВЫБОР_МОДЕЛИ_LLM.md` §4 обновлена.

**Осталось:** интеграция ядра в `memory.js` + APK; загрузчик GGUF в диагностике;
расследование segfault в GBNF-мосте; замер RSS. Живой код не тронут, APK `apk-40`.

## 21.11 — итерация 2: near-duplicate, графовый обход, разбор negativity gate

**Что сделано:** по оставшимся строкам нашей же таблицы research:
- `Proposal-инструменты в MCP` — уже было закрыто (`memory_proposal_accept`,

  нормализует регистр, `ё/е` и пунктуацию, сохраняя порядок слов. Добавлен

- `graphProximity` был дешёвым proxy. Теперь `graphReach()` делает один

## 21.11 — итерация 3: честный baseline bench-гейта

## 21.11 — итерация 4: автономное ядро вместо переписывания движка

## 21.11 — итерация 5: LLM для ядра памяти из research (разбор и честный вывод)

**Что сделано:** по уточнению Макса перечитал `ИССЛЕДОВАНИЕ_ПАМЯТИ_АГЕНТОВ.md`
и нашёл trio Hindsight — `hs-rerank-1` (114M), `hs-embed-1` (112M),
`hs-decide-1-flash` (0.8B, base Qwen3.5-0.8B, apache-2.0). Это единственные
модели в разборе, реально заточенные под память агента.

**Ключевой вывод:** все три не генеративные. `hs-rerank-1`/`hs-embed-1` —
Sentence-BERT, `hs-decide-1-flash` — decision model (`text-ranking`): одним
forward pass выдаёт вероятности вариантов `choice`/`score`/`noul`, без текста.
Наш `libllama-bench.so` умеет `lb_gen`/`lb_gen_g`/`lb_bench` — для корректного
замера нужна новая функция `lb_score` и пересборка .so через CI.

**Попытка и провал:** скачал GGUF `hs-decide-1-flash-bf16.gguf` (1.5 ГБ), но CDN
HuggingFace оборвал соединение на 95 МБ. Битый файл удалён. Даже при успехе
текстовый choice через `lb_gen` был бы некорректным тестом — модель не для
генерации. Решение: не имитировать замер, а зафиксировать требование к мосту.

**Побочный замер:** Qwen3-0.6B (текущая роль объяснений) на 12 gold — формат
100%, привязка к чанку 42%, переформулировка 100%/100%, 7.6 с на пару. Ещё раз
подтверждено: LLM только on-demand, на каждый запрос ядра её не звать.

**Результат:** детерминированное ядро остаётся эталоном (0.850); ни одна из
трёх моделей не имеет held-out доказательства превосходства. Следующий шаг по
желанию Макса — `lb_score` в C-обёртке + повтор скачки кусками + замер на gold.

**Доставка итерации 4:** head `6a3b590881cd…`, CI `44930428796` → success
(Assemble Debug APK и Native build). APK не собирался.

## 21.11 — итерация 6: движок v2 (карта памяти + самообучение), без rewrite

**Что сделано:** по повторному вопросу Макса о переписывании движка (с оглядкой
на Android без root) решение — не переписывать, а надстроить. Добавлен модуль

**Регрессы:** секция 12 в ядре, расширенная проверка ассетов и тулов в
интеграции. Дополнительно: `buildMemoryMap()` self-bootstraps на свежей БД —
карта выучивает закономерности при первом обращении, без явного `mine=true`.
**Результат:** 293/0 + 123/0 + 109/0.

**Важная находка:** APK-ассеты в репо (`app/src/main/assets/mcp/`) отставали от

`memory.js`) синхронизируются этим пушем.
