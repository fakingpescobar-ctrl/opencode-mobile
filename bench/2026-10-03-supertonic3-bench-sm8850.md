# 2026-10-03 — Замер SupertonicTTS 3 int8 `--lang=ru` на SM8850

Первый реальный замер TTS в проекте (задача из `ISSUES_FOR_PC_AGENT_part19.md`, §11.6/§11.7 п.1).

## Стенд

| Что | Значение |
|---|---|
| Железо | Snapdragon 8 Elite Gen 5 (SM8850), 8 ядер Oryon, 14.8 ГБ RAM, Android 16 |
| Провайдер | только CPU (NNAPI +9% и требует статических шейпов, QNN нет — вывод §12.1 подтверждён) |
| Движок | `sherpa-onnx v1.13.8`, prebuilt `android-aarch64-termux-static` + `libc++_shared.so` из NDK 27 |
| Модель | `sherpa-onnx-supertonic-3-tts-int8-2026-05-11` (138 МБ: text_encoder 34.7, vector_estimator 74.8, vocoder 24.8, duration_predictor 3.5, tts.json, unicode_indexer.bin, voice.bin) |
| Команда | `sherpa-onnx-offline-tts --sid=N --lang=ru --num-threads=T --output-filename=... <text>` |
| Тайминг | `/proc/uptime` (в Android `date +%s%N` не работает — только секунды) |
| RSS | опрос `VmHWM` из `/proc/<pid>/status` каждые 200 мс |
| Выход | WAV 44.1 кГц, 2 канала, 16 бит |

Модель и бинарь запускались прямо на телефоне из `/data/local/tmp/ttsbench`, **без пересборки APK** —
это дешёвый путь для замеров (§11.3), и он сработал.

## Тексты

- `short.txt` — 2 предложения, 8.008 с аудио на sid 0.
- `long.txt` — 14 предложений, 76.342 с аудио на sid 0.

## Результат: число потоков

Короткий текст, чередующийся прогон (t1→t2→t3→t4→t6 в каждом повторе, чтобы троттлинг
не доставал только поздние конфиги). RTF = synth/audio, меньше = лучше.

| threads | RTF (прогоны) | Вывод |
|---|---|---|
| 1 | 0.608, 0.612 | однопоточно медленно |
| **2** | **0.320, 0.328, 0.319, 0.325** | **лучший, стабильный** |
| 3 | 0.337, 0.333, 0.577 | двумодальный: то попадает на быстрые ядра, то нет |
| 4 | 0.583, 0.584 | хуже |
| 6 | 0.560, 0.574 | хуже |
| 8 | 0.468–0.611 | хуже |

**Больше потоков — медленнее.** Это главный и контринтуитивный результат: на 8 ядрах
Oryon int8-модель упирается в 2 потока, дальше только накладные расходы и contention
(в момент замеров `loadavg` 10–20, на телефоне параллельно работали Yandex Music,
OneMe и сам opencode-mobile).

## Результат: длинный текст и стабильность

| threads | прогоны | synth, с | audio, с | RTF |
|---|---|---|---|---|
| **2** | 3 | 23.16 / 23.14 / 23.03 | 76.342 | **0.303 / 0.303 / 0.302** |
| 4 | 3 | 28.77 / 28.30 / — | 76.342 | 0.377 / 0.371 |
| 8 | 3 | 37.13 / 40.19 / 38.67 | 76.342 | 0.486 / 0.526 / 0.506 |

На 2 потоках разброс меньше 0.5% — синтез **в 3.3 раза быстрее реального времени**.
На 8 потоках разброс 8% и абсолютное время на 60% хуже.

## Результат: память

| текст | audio, с | peak RSS |
|---|---|---|
| short | 8.0 | 309 МБ |
| long | 76.3 | 428 МБ |
| long, 4 потока | 76.3 | 429 МБ |

Прирост +119 МБ на +68 с аудио → **≈1.75 МБ на секунду звука**. То есть состояние
не растёт, как при O(T) на предложение, но и не абсолютно константно: 90-секундный
ответ даст ~460–470 МБ. При 14.8 ГБ RAM это не ограничение, но порог
(`--max-duration` или аналог) ставить надо — на длинных ответах память всё же растёт.

## Результат: TTFA

- Холодный старт (загрузка модели): wall 3.74 с против 2.57 с синтеза → **≈1.2 с на модель**.
- Предложение ≈4 с аудио → синтез ≈1.3 с при 2 потоках.
- Ориентир из §12.5 «первый звук в пределах ~1 с» **не достигается** на границе предложения:
  получается ~1.3–1.5 с, и это с учётом того, что модель уже загружена.

Чтобы попасть в ~1 с, нужен первый чанк короче предложения — резать по первой же
границе предложения, а если предложение длинное, дополнительно по `;`/`:`. Это ровно
то, что уже заложено в §12.5 п.2 («можно разделить по `;`/двоеточию, если предложение
не получается слишком длинным»).

## Вывод

1. Движок **работает на телефоне, русский голос есть, синтез быстрее реального времени
   в 3.3 раза** при 2 потоках. Обязательное требование «русский» выполнимо.
2. Озвучка с выключателем реализуема: предложение синтезируется за ~1.3 с, аудио
   4 с, значит запас по времени есть, шов не будет слышен.
3. Конфигурация для приложения: `--num-threads=2`, модель в `files/models/tts/`,
   warmsplash 1.2 с при первом запуске.
4. Осталось только выбрать `--sid` прослушиванием — этого автоматика не заменит.

## Образцы для прослушивания

`bench/samples/`: `sid0-short.wav` … `sid4-short.wav` (по 7–8 с, текст `short.txt`),
`sid0-long.wav` (76 с). Скорость от `--sid` не зависит (RTF 0.312–0.331 на sid 0–4).
