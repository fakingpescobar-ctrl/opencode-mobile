# Эталоны для WER-бенча

Здесь лежат **вручную написанные** расшифровки речи для подсчёта WER.
Формат: `reference/<имя wav без расширения>.txt`, ровно один файл на wav.

## Почему папка пустая

Эталон нельзя составить по выводу модели. Если так сделать, WER получится около
нуля и будет выглядеть как отличный результат, не измеряя ничего. Поэтому
расшифровки пишутся отдельно, до прогона, и хранятся в git рядом с wav.

Пока файлов нет, в колонке `wer` CSV стоит прочерк. Это честнее нуля: нуля
не существует, пока не с чем сравнивать.

## Что нужно

| Файл | Что в нём | Для чего |
|---|---|---|
| `jfk.txt` | точная расшифровка `jfk.wav` | базовый замер, короткая чистая речь |
| `long.txt` | точная расшифровка `long.wav` (37 с, три высказывания) | проверка чанкинга: не теряется ли хвост и склейка |

`noise.wav`, `silence.wav`, `tone.wav` — не речь, эталонов для них не бывает.
Файлы-эталоны без парного `.wav` отбрасываются с warning, пустые тоже.

## Как записать

1. Послушать wav и **переписать словами, что там сказано**. Не скопировать из
   вывода модели, не описать своими словами — дословно, со слова-паразитами.
2. Один абзац, обычный текст. Переносы строк допустимы, сравнение их игнорирует.
3. Знаки препинания можно не ставить — сравнение их срезает. Регистр и `ё`/`е`
   тоже не важны.

## Что будет дальше

Запуск на устройстве с ncnn-моделями:

```
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=org.opencode.mobile.BenchSttTest
```

или из Android Studio: `BenchSttTest` -> `benchInt8VsFp32`. CSV с колонкой
`wer` пишется в `/sdcard/AndroidData/org.opencode.mobile.debug/files/stt-bench.csv`.

Сравнение word-level, формула — `stt/Wer.kt` (покрыта 13 юнит-тестами). Слова-паразиты
(`ну`, `вот`, `это`) **не выбрасываются**: выкидывать их на стороне сравнения
значит подгонять метрику под удобный результат.
